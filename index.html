Market expansion, oracle reliability and governed releases

Five synthetic markets, with real trading hours

Built a tool that checks out chosen branches of the program, its interface package, two keepers and the data service and tests them together on a local validator or devnet.

Volume and trader figures describe platform activity during my tenure, not growth attributed to me. The batch figure is an estimate from database id counters for what the ingestion job stored, not a count of confirmed on-chain transactions. Adrena wound down trading in 2026.

Proof on mainnet

In the first acceptance run (19 Sep 2026) I verified eight finalized mainnet transactions: fee-account setup, six swaps and one fee claim. A separate checker reconciled each fee as floor(base × 50 / 10,000), sequential balances and minimum receipts for that run. The 0.50% fee settles in SOL, USDC or USDT, and NABLA's share is claimed into a multisig treasury that needs two signatures.

The swap figure comes from NABLA's public ledger and DefiLlama's fee data, to 12 Nov 2026. It measures what the system has settled, not user growth.

I do the engineering and run the services; program upgrades and treasury payments go through a multisig.

Recovery checks and Android release engineering

Changes rehearsed before production

Every schema or data change is first run on an isolated copy, with before and after fingerprints and deliberately injected faults. The first rehearsal confirmed that all 69 existing table definitions were unchanged and caught both injected faults. On 27 Sep 2026 I drilled a point-in-time restore of the production database: 234 MB restored in about 6 minutes and compared with production table by table.

Load-tested the live API with 100 simulated users making real small swaps. After fixes and a larger instance, the 95th-percentile wait to prepare a swap fell from 37 s to 7.5 s and no signed trade was lost.

Source-to-release checks

A GitHub Actions check rebuilds the Android app's code, JavaScript bundle and resources from a fresh checkout on every push and compares them file by file with the committed release. Actions are pinned by commit SHA, the Gradle distribution is pinned by checksum and the 36 third-party native libraries are locked by SHA-256. On its first day the check caught a release that carried the build machine's network address.

Android work is committed under my second GitHub account, in a private repository.

Vault accounting, failure controls and evidence

Money and execution boundaries

Implemented exposure limits in the keeper: advances are tracked in token quantity, valued at the current price and capped against net asset value. When a balance read fails, the keeper refuses to act instead of treating the failure as zero.

Data that can be checked again

For the 39 daily exports from 1 August to 8 September 2026, all four core telemetry streams matched their committed SHA-256 hashes and line counts.

The retained exports form an evidence trail whose file integrity can be checked again. Quant models came from my collaborator; I implemented, tested and operated the system.
