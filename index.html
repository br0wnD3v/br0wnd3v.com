Edge detection and SIM constraints

From training data to field detection

Built the device software around Raspberry Pi 4B, thermal/IR cameras and Coral Edge TPU hardware. Collected and annotated the data used to train the YOLOv8 models, then integrated detection, alerts and acoustic deterrence into the device workflow.

The resulting elephant-deterrence system was deployed with the Chhattisgarh Forest Department.

Designing around the radio module

The SIM module’s 64K-byte payload ceiling and HTTP-only support shaped the device-to-cloud path. The device sent requests to a fixed public IP on Lightsail; the relay forwarded them to the Railway service.

The ingestion service validated device identifiers, GPS coordinates, timestamps and detection confidence, acknowledged intake promptly, and handled S3 uploads and metadata writes in the background with retries and health checks.

Cloud route and storage migration

Metadata: RDS → Supabase

The original cloud backend stored sighting metadata in Amazon RDS. Later moved that storage to Supabase for cost reasons, retaining confidence constraints, device/time indexes and unique image keys in the ingestion data model.

Images stayed in S3

Images continued to live in AWS S3 through the metadata migration. The backend’s background upload and database-write paths included retry handling and service health endpoints.
